객체 탐지(YOLO) 기반 작물 분석 실습 과제
================================================================================

완숙/미숙 토마토 데이터셋(Ripe and Unripe Tomatoes Dataset.zip)을 사용하여
Ultralytics YOLO26 객체 탐지 모델을 학습하고, 학습된 가중치를 저장·불러와
예측한 뒤 숙도 비율로 수확 판정을 수행하는 작물 분석 실습이다.

구현 환경은 Google Colab + GPU (로컬 CUDA GPU도 가능) 이다.
완성 코드는 이 문서의 설정·출력 형식을 따라야 한다.


1. 실습 목표
--------------------------------------------------------------------------------
- zip을 풀어 detection/images 와 detection/labels 를 찾는다.
- YOLO txt 라벨(class xc yc w h, 정규화 좌표)로 메타데이터·EDA를 수행한다.
- Ultralytics YOLO 형식으로 train/val/test 를 분할하고 data.yaml 을 작성한다.
- COCO 사전학습 YOLO26n(yolo26n.pt)을 파인튜닝한다.
- best.pt 를 models/ 폴더에 저장한 뒤, 그 파일만 다시 로드하여 예측한다.
- test 이미지의 미숙/완숙 개수와 완숙 비율로 수확 판정을 출력한다.

3. 데이터
--------------------------------------------------------------------------------
사용할 zip:

    Ripe and Unripe Tomatoes Dataset.zip

zip 내부 구조(폴더가 한 겹 더 있어도 됨):

    detection/
     ├─ images/                 # riped_tomato_*.jpeg, unriped_tomato_*.jpeg
     ├─ labels/                 # YOLO txt (class xc yc w h)
     └─ coco_annotations.json
    segmentation/               # 본 실습에서는 사용하지 않음

데이터 규모(이 숫자와 맞아야 함):

    탐지용 이미지 177장, 라벨 177개 (1:1)
    객체(박스) 약 869개
    클래스 2종

클래스 (YOLO class id)

    id   영문      한글
    --   --------  ----
    0    unripe    미숙
    1    ripe      완숙

YOLO 라벨 예시 (riped_tomato_1.txt):

    1 0.446946 0.228366 0.122019 0.193065   # ripe
    0 0.464426 0.636520 0.143270 0.126523   # unripe

한 이미지에 완숙·미숙 객체가 함께 등장할 수 있다.
파일명(riped_ / unriped_)은 사진 단위 태그이고,
txt의 class id는 객체 단위 숙도이다. 혼동하지 말 것.

데이터 출처:

    Kaggle — Riped and Unriped Tomato Dataset
    https://www.kaggle.com/datasets/sumn2u/riped-and-unriped-tomato-dataset/data

data.yaml 필수 내용:

    path: {WORK_DIR 절대경로}
    train: images/train
    val: images/val
    test: images/test
    nc: 2
    names:
      0: unripe
      1: ripe

수확 판정 기준 (바꾸면 안 됨):

    HARVEST_HIGH = 0.70   # 완숙비율 >= 0.70 → 수확 권장
    HARVEST_MID  = 0.40   # 0.40 ~ 0.70 → 부분 수확
                          # < 0.40 → 생육 관찰
                          # 객체 0개 → 객체 없음

YOLOv8 / YOLOv5 / Detectron2 등 다른 탐지 프레임워크는 사용하지 않는다.
yolo26s.pt 로 바꾸거나 epochs 를 바꾸는 것은 제출본에서 금지한다.

문제 1. 패키지 설치, 한글 폰트, GPU 확인
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
1) ultralytics 및 시각화 패키지를 설치한다.
   PyTorch는 설치하지 않는다.

    %pip install -q "ultralytics>=8.4.0" seaborn scikit-learn pandas pyyaml opencv-python-headless

2) IN_COLAB 을 다음처럼 판별한다.

    try:
        from google.colab import files, drive
        IN_COLAB = True
    except ImportError:
        IN_COLAB = False

3) Colab에서 시각화 시 한글이 깨지지 않도록 한글 폰트를 설치·적용한다.
   함수 이름: setup_korean_font()

   Colab(IN_COLAB=True)일 때:

    fonts-nanum 설치 (apt-get)
    /usr/share/fonts/truetype/nanum/NanumGothic.ttf 를 matplotlib에 등록
    plt.rc("font", family=...)
    plt.rcParams["axes.unicode_minus"] = False

   로컬(IN_COLAB=False)일 때는 OS에 설치된 한글 폰트를 찾거나,
   NanumGothic / Malgun Gothic / AppleGothic 중 사용 가능한 것을 적용한다.
   폰트를 못 찾으면 경고만 출력하고 계속 진행한다.

   설치·적용 후 아래를 출력한다.

    한글 폰트: NanumGothic  (...경로...)

   (로컬에서 다른 폰트를 쓰면 그 폰트 이름을 출력)

   EDA, 예측 결과 제목 등 한글이 들어가는 모든 그래프는
   이 폰트 설정이 적용된 뒤에 그려야 한다.

4) select_compute_device() 를 구현한다.
   - torch.cuda.is_available() 이면 DEVICE=0, USE_CUDA=True
   - 아니면 DEVICE="cpu", USE_CUDA=False
   - CUDA일 때 cudnn.benchmark, TF32, set_float32_matmul_precision("high") 를 켠다
     (함수가 있을 때만)

5) DEVICE, USE_CUDA, gpu_name, vram_gb, USE_GPU(= DEVICE != "cpu") 를 저장한다.

6) 아래 형식으로 출력한다.

    연산 장치     : GPU (cuda:0)   또는 CPU
    GPU 이름      : ...            (GPU일 때)
    VRAM          : ... GB         (GPU일 때)
    PyTorch CUDA  : ...            (GPU일 때)
    실행 환경     : Google Colab 또는 로컬
    OS            : ...
    Ultralytics   : ...
    PyTorch       : ...
    Device 인자   : 0 또는 cpu
    GPU 사용      : True 또는 False

7) (선택·권장) torchvision 이 CPU 빌드여서 CUDA NMS가 없으면
   Ultralytics TorchNMS 로 대체하는 패치를 넣어도 된다.
   단, torch / torchvision 을 pip 으로 설치·교체하지 않는다.

문제 3. EDA — 메타데이터 구축
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
이미지·라벨을 짝지어 DataFrame 두 개를 만든다.

   각 줄에서 cls, xc, yc, w, h, area(=w*h) 를 읽는다.

2) filename_group(stem) → "ripe" | "unripe" | "unknown"
   파일명에 unriped/unripe 가 있으면 unripe,
   riped/ripe 가 있으면 ripe.

    컬럼         설명

    width        가로(px)
    height       세로(px)
    pixels       width * height
    aspect       width / height
    n_box        박스 개수
    n_unripe     class 0 개수
    n_ripe       class 1 개수
    has_both     미숙·완숙이 동시에 있으면 1
    file_group   filename_group 결과

4) df_box (객체/박스 단위) 컬럼을 반드시 포함한다.

    file, file_group, width, height, cls, cls_ko,
    xc, yc, bw, bh, area_norm, box_w_px, box_h_px

5) 아래를 출력한다.

    이미지 수        : 177
    라벨 파일 수     : 177
    객체(박스) 수    : 869
    라벨 없는 이미지 : 0

이어서 df_img.head() 와 수치형 describe() 를 출력한다.

7. 구현 시 주의사항
--------------------------------------------------------------------------------
- 학습 전에 GPU 런타임을 선택한다. (로컬도 CUDA GPU 권장)
- 첫 실행 시 yolo26n.pt 를 자동 다운로드한다. 네트워크가 필요하다.
- Colab matplotlib 기본 폰트는 한글을 지원하지 않는다.
  문제 1에서 fonts-nanum(NanumGothic)을 설치·등록한 뒤 EDA를 그린다.
  런타임을 다시 시작하면 폰트 설치 셀을 다시 실행해야 한다.
- zip 파일명에 공백이 있어도 경로로 처리할 수 있어야 한다.
- 파일명 태그(riped_/unriped_)와 객체 class id(0/1)를 혼동하지 않는다.
- Windows Jupyter 에서는 WORKERS=0 이 안정적이다.
- torchvision 이 CPU 빌드이면 GPU NMS에서 NotImplementedError 가 날 수 있다.
  TorchNMS 대체 패치로 해결하되, PyTorch 재설치는 하지 않는다.
- 클래스 이름, 출력 문구, 하이퍼파라미터는 이 문서에 적힌 그대로 사용한다.
- mAP 숫자 자체는 GPU/라이브러리 버전에 따라 조금 달라질 수 있다.
  채점은 설정과 출력 형식, 동작을 본다.
- 제출물에 데이터 출처(Kaggle Ripe and Unripe Tomato Dataset)를 남긴다.
