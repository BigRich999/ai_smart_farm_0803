# OpenAI 기반 VLM 농업 질의응답 시스템 — 소스 기능 설명

이 문서는 `01_OpenAI 사용` 폴더 소스의 **목적, 파일별 기능, 처리 흐름, 설정, 실행 방법**을 자세히 설명합니다.

---

## 1. 프로젝트 개요

### 1.1 무엇을 하는 시스템인가

고추·무·배추 **농작물 이미지**를 OpenAI Vision(VLM)으로 분석하고,  
농업기술 **PDF 지식베이스(RAG)**에서 관련 문서를 검색한 뒤,  
LLM이 **증상·원인·발생 환경·관리 방법·참고 문서**를 포함한 답변을 생성하는  
**멀티모달 농업 질의응답 웹앱**입니다.

### 1.2 기술 스택

| 구분 | 기술 |
|------|------|
| UI | Streamlit |
| VLM (이미지 분석) | OpenAI `gpt-4o-mini` (Vision) |
| LLM (최종 답변) | OpenAI `gpt-4o-mini` |
| Embedding | OpenAI `text-embedding-3-small` |
| Vector DB | Chroma (`langchain-chroma`) |
| PDF 처리 | pypdf |
| 문서 분할 | LangChain `RecursiveCharacterTextSplitter` |
| API 키 | `C:\env\.env`의 `OPENAI_API_KEY` |

### 1.3 02_Qwen3-VL 실습과의 차이

| 항목 | 01_OpenAI (본 폴더) | 02_Qwen3-VL |
|------|---------------------|-------------|
| 이미지 분석 | OpenAI Vision API | Qwen3-VL 로컬/API |
| 최종 답변 | OpenAI Chat Completions | Qwen3-VL 텍스트 생성 |
| Embedding | OpenAI API | 로컬 `BAAI/bge-m3` |
| GPU 필요 | 없음 (API 호출) | 로컬 시 GPU 권장 |
| Chroma 경로 | `_vlm_agri_chroma` | `_vlm_agri_chroma_qwen3vl` |

### 4.2 `vlm_analyzer.py` — VLM 이미지 분석

농작물 이미지를 OpenAI Vision에 보내 **구조화된 JSON**으로 변환합니다.

#### 주요 함수

| 함수 | 기능 |
|------|------|
| `encode_image` / `encode_image_bytes` | 이미지를 base64 + MIME으로 인코딩 |
| `_call_vlm` | Chat Completions에 텍스트+이미지 전송 (`detail: high`) |
| `_extract_json` | 모델 응답에서 JSON 파싱 (코드펜스 제거 포함) |
| `_normalize_analysis` | 필드 정규화, `confidence`↔`severity` 정합, 모순 교정 |
| `_looks_under_diagnosed` | 문제 질문인데 `정상`+무증상인지 판별 |
| `analyze_crop_image` | 1차 분석 + 필요 시 재분석 |
| `build_search_query` | RAG용 검색 질의 문자열 생성 |

#### 분석 JSON 스키마

```json
{
  "crop": "고추|무|배추|기타|불명",
  "health_status": "정상|질병의심|판단불가",
  "observed_symptoms": ["증상1", "증상2"],
  "suspected_diseases": ["의심질병1"],
  "severity": "low|medium|high",
  "confidence": "low|medium|high",
  "summary": "한글 2~4문장 요약"
}
```

#### 판정·보정 로직

1. **프롬프트**: 병반·변색·위축 등이 보이면 `질병의심`을 우선. 정상을 기본값으로 두지 않음.
2. **정규화**: 증상/의심병이 있는데 `정상`이면 → `질병의심`으로 교정.
3. **재분석**: 사용자가 문제·증상을 묻는데 결과가 `정상`+무증상이면 Vision을 **한 번 더** 호출.
4. **검색어**: `정상`은 RAG 질의에서 제외. 증상/질병이 비면 작물별 대표 병해 키워드 보완  
   (예: 고추 → 탄저병, 무름병).

#### API 호출 특징

- 모델: `VLM_MODEL` (`gpt-4o-mini`)
- `temperature=0.1` (일관성 우선)
- 이미지 `detail: "high"` (병반 식별을 위해 고해상도 전달)

### 4.3 `rag_store.py` — PDF RAG 지식베이스

농업기술 PDF를 읽어 임베딩하고, 질의에 대해 유사 문서를 검색합니다.

#### 처리 파이프라인

```
PDF 파일
  → extract_pdf_pages()          # pypdf 페이지 텍스트
  → load_or_extract_pdf_cache()  # cache/pdf_texts.json
  → (+ 배추 보완 txt)
  → pages_to_documents()         # LangChain Document
  → split_documents()            # chunk 900 / overlap 150
  → OpenAIEmbeddings
  → Chroma.from_documents()
  → similarity_search(query, k=6)
```

#### 함수별 역할

| 함수 | 기능 |
|------|------|
| `_file_fingerprint` | PDF 경로·수정시각·크기로 캐시 무효화 키 생성 |
| `extract_pdf_pages` | 페이지 텍스트 추출 (40자 미만 페이지 스킵) |
| `load_or_extract_pdf_cache` | 캐시 hit 시 재추출 생략, miss 시 추출 후 저장 |
| `pages_to_documents` | `{text, source, page}` → `Document` |
| `split_documents` | 재귀 문자 분할기로 청킹 |
| `get_embeddings` | `OpenAIEmbeddings(model=text-embedding-3-small)` |
| `build_vectorstore` | Chroma 구축; `.ready` 마커로 완료 표시 |
| `load_vectorstore` | DB 로드 (없으면 자동 구축) |
| `search_knowledge` | 유사도 검색 top-k |
| `format_retrieved_context` | LLM에 넣을 컨텍스트 문자열 + 출처 문서명 목록 |

#### 배추 PDF 보완

`농업기술길잡이128_배추.PDF`는 스캔 이미지 위주라 텍스트 추출이 거의 되지 않습니다.  
그래서 `knowledge_supplement/배추_병해충_요지.txt`를  
출처명 `농업기술길잡이128_배추.PDF (보완요약)`으로 함께 인덱싱합니다.

보완 요약에 포함된 병해 예: 무름병, 세균성 검은썩음병, 노균병, 균핵병 등.

#### Vector DB 재구축

- 정상 로드: `CHROMA_DIR/.ready`가 있으면 기존 DB 사용
- 강제 재구축: `build_vectordb.py --force` → 디렉터리 삭제 후 재생성  
  (PDF 텍스트 캐시는 fingerprint가 같으면 재사용)

### 4.5 `qa_pipeline.py` — 통합 파이프라인

UI와 개별 모듈을 잇는 **오케스트레이터**입니다.

#### `run_multimodal_qa(image_source, user_question, filename)`

1. `OpenAI()` 클라이언트 1개 생성 (VLM·LLM 공유)
2. `analyze_crop_image` → 이미지 분석 dict
3. `build_search_query` → RAG 질의 문자열
4. `search_knowledge` → Document 리스트
5. `format_retrieved_context` → `(context, sources)`
6. `generate_final_answer` → 최종 답변 문자열

#### 반환값

```python
{
  "analysis": {...},          # VLM JSON (+ raw_model_output 등)
  "search_query": "...",      # RAG에 넣은 질의
  "retrieved_docs": [         # UI 미리보기용
    {"source": "...", "page": n, "preview": "앞 240자"}
  ],
  "sources": ["문서명", ...], # 중복 제거된 참고 문서
  "answer": "..."             # LLM 최종 답변
}
```

#### `generate_final_answer`

- 시스템 프롬프트: 문서 근거만 사용, 확진 금지, 필수 6항목 포함
- 사용자 프롬프트: 질문 + VLM 분석 + RAG 컨텍스트 + 참고 문서 후보
- `temperature=0.3`
- 이미지는 **다시 보내지 않음** (분석 JSON + 문서만으로 답변)

최종 답변에 반드시 포함하도록 요구하는 항목:

1. 이미지 분석 결과  
2. 주요 증상  
3. 발생 원인  
4. 발생 환경  
5. 관리 방법  
6. 참고 문서

## 5. 엔드투엔드 시나리오 예시

**입력**

- 이미지: `배추_질병` 샘플
- 질문: `이 배추에 어떤 문제가 있는 것 같나요? 증상과 관리 방법을 알려주세요.`

**처리**

```
이미지 + 질문
  → [VLM] crop=배추, health_status=질병의심,
           symptoms=[잎 황화, ...], diseases=[무름병, ...]
  → [검색어] "배추 병해충 배추 병해 질병의심 잎 황화 무름병 ..."
  → [RAG] PDF/보완요약에서 top-6 청크 검색
  → [LLM] 증상·원인·환경·관리·참고문서 종합 답변
```

**출력 (UI)**

- 작물 / 상태 / 신뢰도
- 관찰 증상, 의심 질병, 요약
- RAG 검색 질의
- 검색된 농업기술 조각
- 최종 답변 + 참고 문서명

## 10. 운영·디버깅 참고

1. **API 키 오류**  
   `OPENAI_API_KEY`가 없으면 Vision·Embedding·Chat이 모두 실패합니다.

2. **Vector DB 없음**  
   사이드바에 경고가 뜹니다. `build_vectordb.py`를 먼저 실행하거나,  
   앱에서 검색 시 `load_vectorstore()`가 자동 구축을 시도합니다.

3. **배추 답변이 빈약할 때**  
   스캔 PDF + 보완 txt 인덱싱 여부를 확인하세요.  
   `--force`로 재구축 후 다시 검색합니다.

4. **진단이 ‘정상’으로만 나올 때**  
   `vlm_analyzer`의 병징 우선 프롬프트·재분석·검색어 보완이 동작합니다.  
   그래도 틀리면 이미지 품질·조명·다른 샘플로 재시도하세요.  
   본 시스템은 **확진이 아닌 의심 수준** 상담 도구입니다.

5. **비용**  
   질의 1회 ≈ Vision 1~2회 + Embedding(검색) + Chat 1회.  
   Vector DB 구축 시에는 청크 수만큼 Embedding API가 호출됩니다.
