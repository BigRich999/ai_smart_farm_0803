## 1. 실습 위치와 목적


### 4.3 `qwen_client.py` — Qwen3-VL 클라이언트

VLM/LLM 호출의 **유일한 진입점**입니다.

```
qwen_generate(system_prompt, user_text, image_source=None, ...)
        │
        ├─ resolve_backend() → "local" | "api"
        │
        ├─ local → _generate_local()
        │            ├─ _load_local_model()  (싱글톤)
        │            ├─ 이미지 리사이즈(긴 변 ≤ 1536)
        │            ├─ processor + model.generate
        │            ├─ threading.Lock (연속 질의 충돌 방지)
        │            └─ CUDA empty_cache (VRAM 잔류 완화)
        │
        └─ api → _generate_api()
                   OpenAI 호환 Chat Completions
                   (DashScope / vLLM / Ollama 등)
```

**주요 설계 포인트**

- 모델·프로세서 모듈 전역 싱글톤 → Streamlit 재실행 시 재로딩 방지
- `device_map=auto`, VRAM 부족 시 4bit 양자화 자동 선택 가능
- 로컬 추론 시 생성 락 + 캐시 정리 → **두 번째 질의부터 멈추는 현상** 완화
- `describe_runtime()` → UI 사이드바에 backend/GPU 정보 표시

### 4.4 `vlm_analyzer.py` — 이미지 분석

`qwen_generate`에 이미지+프롬프트를 넣어 **JSON 구조화 결과**를 만듭니다.

**출력 스키마**

```json
{
  "crop": "고추|무|배추|기타|불명",
  "health_status": "정상|질병의심|판단불가",
  "observed_symptoms": ["..."],
  "suspected_diseases": ["..."],
  "severity": "low|medium|high",
  "confidence": "low|medium|high",
  "summary": "한글 요약"
}
```

**동작 흐름**

1. 병징 우선 탐지 프롬프트로 1차 분석
2. `_normalize_analysis`: 증상/질병이 있는데 `정상`이면 → `질병의심`으로 교정, `confidence`↔`severity` 정합
3. 사용자가 문제·증상을 묻는데 결과가 `정상`+무증상이면 **재분석 1회**
4. `build_search_query`: RAG용 질의 문자열 생성
   - `정상`은 검색어에서 제외
   - 증상/질병이 비면 작물별 대표 병해 키워드 보완 (예: 고추→탄저병, 무름병)

---

### 4.5 `rag_store.py` — 지식베이스 / RAG

PDF → 텍스트 → 청크 → 임베딩 → Chroma → 유사도 검색.

| 함수 | 역할 |
|------|------|
| `extract_pdf_pages` | pypdf로 페이지 텍스트 추출 |
| `load_or_extract_pdf_cache` | `cache/pdf_texts.json` 캐시 |
| `pages_to_documents` / `split_documents` | LangChain Document + RecursiveCharacterTextSplitter |
| `get_embeddings` | `HuggingFaceEmbeddings` 싱글톤 |
| `build_vectorstore` | Chroma 구축, `.ready` 마커 기록 |
| `load_vectorstore` | 기존 DB 로드(없으면 구축) |
| `search_knowledge` | `similarity_search(query, k)` |
| `format_retrieved_context` | 답변용 컨텍스트 문자열 + 출처 목록 |

**Embedding 디바이스 정책**

- 로컬 Qwen3-VL과 GPU를 나누면 VRAM 고갈 → 기본 **CPU**
- `EMBEDDING_DEVICE=cuda`로 강제 가능

**배추 PDF 보완**

`농업기술길잡이128_배추.PDF`는 스캔본이라 텍스트 추출이 거의 안 됩니다.  
`knowledge_supplement/배추_병해충_요지.txt`를 함께 인덱싱합니다.

### 4.6 `build_vectordb.py` — Vector DB CLI

```bash
python build_vectordb.py          # 없으면 구축, 있으면 로드만
python build_vectordb.py --force  # 삭제 후 재구축
```

내부적으로 `rag_store.build_vectorstore()`만 호출하는 얇은 래퍼입니다.  
앱 첫 실행 시 DB가 없으면 `load_vectorstore()`가 자동 구축하지만, **사전 구축을 권장**합니다.

### 4.7 `qa_pipeline.py` — 파이프라인 오케스트레이션

핵심 API:

```python
run_multimodal_qa(image_source, user_question, filename) -> dict
```

반환 딕셔너리:

```python
{
  "analysis": {...},           # VLM JSON
  "search_query": "...",       # RAG 질의
  "retrieved_docs": [...],     # 미리보기용
  "sources": [...],            # 문서명 목록
  "answer": "..."              # 최종 답변 마크다운/텍스트
}
```

최종 답변은 이미지를 다시 넣지 않고, **분석 JSON + RAG 컨텍스트**만 Qwen에 전달합니다.

## 6. 백엔드 선택 로직

`qwen_client.resolve_backend()`:

```
QWEN_BACKEND=local  → 항상 로컬 Transformers
QWEN_BACKEND=api    → 항상 OpenAI 호환 API
QWEN_BACKEND=auto   → QWEN_API_BASE 있으면 api, 없으면 local
```

### 로컬 예시 (`.env`)

```env
QWEN_BACKEND=local
QWEN_VL_MODEL=Qwen/Qwen3-VL-4B-Instruct
QWEN_QUANTIZATION=4bit
EMBEDDING_MODEL=BAAI/bge-m3
```

### API 예시 (DashScope)

```env
QWEN_BACKEND=api
QWEN_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_API_KEY=sk-...
QWEN_API_MODEL=qwen3-vl-plus
```

## 10. 운영 시 주의사항

1. **VRAM**  
   로컬 4B + 이미지 생성 2회(+재분석)는 메모리를 많이 씁니다.  
   Embedding은 기본 CPU. 부족하면 `4bit` 또는 `Qwen3-VL-2B-Instruct`.

2. **두 번째 질의 지연/멈춤**  
   생성 락·캐시 정리·이미지 축소가 적용되어 있습니다.  
   여전히 멈추면 Streamlit 완전 재시작 후 `QWEN_QUANTIZATION=4bit` 확인.

3. **진단 정확도**  
   소형 VLM은 병징을 놓칠 수 있습니다.  
   프롬프트·재분석·검색어 보완으로 완화하지만, **확진이 아닌 의심 수준**으로 해석해야 합니다.

4. **한글 경로**  
   코드/데이터는 한글 폴더에 두어도 되지만, Chroma persist는 ASCII 경로를 유지하세요.

5. **캐시**  
   PDF 텍스트는 `cache/pdf_texts.json`에 남습니다. PDF를 바꾸면 `build_vectordb.py --force`로 재구축하세요.
